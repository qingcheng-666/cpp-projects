## ① Node 类：节点长什么样

```cpp
template<typename K, typename V> 
class Node {
public:
    Node() {} 
    Node(K k, V v, int); 
    ~Node();
    K get_key() const;
    V get_value() const;
    void set_value(V);
    
    // Linear array to hold pointers to next node of different level
    Node<K, V> **forward;      // ← 最关键的一行
    int node_level;

private:
    K key;
    V value;
};
```

### 关键点 1：`template<typename K, typename V>`

`K` 是 key 的类型，`V` 是 value 的类型。所以 `Node<int, std::string>` 就是"key 是 int、value 是 string 的节点"。

原版 `main.cpp` 用的是 `SkipList<int, std::string>`。

### 关键点 2：`Node<K, V> **forward`

**这是全文最重要的一行，一定要看懂。**

- `Node<K,V>*` 是"指向一个节点的指针"
- `Node<K,V>**` 是"指向指针的指针" → 实际上它指向的是**一个指针数组的首元素**

换句话说：`forward` 是一个**指针数组**，`forward[i]` 表示"**我在第 i 层的下一个节点**"。

```
一个层高为 2 的节点（node_level = 2）：

    forward ──┐
              ▼
         ┌────────┬────────┬────────┐
         │forward │forward │forward │
         │  [0]   │  [1]   │  [2]   │
         └───┬────┴───┬────┴───┬────┘
             │        │        │
             ▼        ▼        ▼
          第0层下一个  第1层下一个  第2层下一个
           (全部节点)  (稀疏)     (更稀疏)
```

数组长度 = `node_level + 1`（因为下标从 0 开始）。

### 关键点 3：构造函数里的内存分配

```cpp
template<typename K, typename V> 
Node<K, V>::Node(const K k, const V v, int level) {
    this->key = k;
    this->value = v;
    this->node_level = level; 

    // level + 1, because array index is from 0 - level
    this->forward = new Node<K, V>*[level+1];      // ← 分配 level+1 个指针
    
    // Fill forward array with 0(NULL) 
    memset(this->forward, 0, sizeof(Node<K, V>*)*(level+1));   // ← 全填 NULL
};
```

- `new Node<K,V>*[level+1]`：分配一个**能装 level+1 个节点指针**的数组
- `memset(..., 0, ...)`：把这 `level+1` 个指针**全部置为 NULL**

> **为什么要 memset？** 因为 `new` 出来的内存**不会自动清零**，里面是垃圾值。不置 NULL 的话，
> `forward[i]` 就是个野指针，遍历时会直接崩溃。

### 关键点 4：析构函数

```cpp
template<typename K, typename V> 
Node<K, V>::~Node() {
    delete []forward;      // ← 注意是 delete[]，因为 new 的是数组
};
```

`new[]` 配 `delete[]`，`new` 配 `delete`，不能搞混。

> ⚠️ **注意**：这里只释放了 `forward` 数组本身，**没有释放它指向的其他节点**。
> 那些节点由 `SkipList` 的析构函数统一负责。这是正确的设计——否则会重复释放。

### 关键点 5：getter/setter

```cpp
K get_key() const { return key; }
V get_value() const { return value; }
void set_value(V value) { this->value=value; }
```

**这里有个值得注意的细节**：`set_value()` 在整个项目里**从未被调用过**。

为什么？因为 `insert_element()` 遇到已存在的 key 时**直接返回，不覆盖旧值**。所以 `set_value()` 是**死代码**。

> 这意味着：**原版的跳表没有"更新"语义**。想改一个 key 的值，只能先 `delete_element` 再 `insert_element`。
> 这是面试可以主动提的一个点。

## ② SkipList 的成员变量

```cpp
private:    
    int _max_level;              // 允许的最大层数（main 用 6，压测用 18）
    int _skip_list_level;        // 当前实际最高层（动态变化）
    Node<K, V> *_header;         // 头节点指针
    std::ofstream _file_writer;  // 落盘用
    std::ifstream _file_reader;  // 加载用
    int _element_count;          // 元素个数
```

### `_max_level` vs `_skip_list_level` 的区别（容易混）

| | 含义 | 会不会变 |
|---|---|---|
| `_max_level` | 层数的**上限**，构造时定死 | ❌ 不变 |
| `_skip_list_level` | **当前**用到了第几层 | ✅ 插入时可能抬高，删除时可能降低 |

举例：`_max_level = 6`，刚开始 `_skip_list_level = 0`（只有 L0）。
插入一个随机层高为 3 的节点后，`_skip_list_level` 变成 3。此时 L4、L5 虽然分配了，但没用上。

> 对应可视化程序里的输出：
> ```
> L4 ┆ H   (空，还没用到)      ← _skip_list_level = 3，所以 L4 显示为"没用上"
> L3 │ H ------>3 ---->19
> ```

### `_header` 是什么

**头节点，不存业务数据**，作用是**作为每一层的起点**。

```cpp
K k;   // 默认构造一个 K（int 就是 0，但不会被用到）
V v;   // 默认构造一个 V
this->_header = new Node<K, V>(k, v, _max_level);   // ← 层高 = _max_level（最高）
```

注意头节点的层高是 **`_max_level`**（不是 `_skip_list_level`），因为它要能"够到"任何一层。

> 可视化图里那个 `H` 就是它。

## ③ 构造函数 / 析构函数

### 构造函数

```cpp
template<typename K, typename V> 
SkipList<K, V>::SkipList(int max_level) {
    this->_max_level = max_level;
    this->_skip_list_level = 0;        // 初始只有 L0
    this->_element_count = 0;

    K k;
    V v;
    this->_header = new Node<K, V>(k, v, _max_level);
};
```

很直白：初始化计数、创建头节点。

### 析构函数（**有坑**）

```cpp
template<typename K, typename V> 
SkipList<K, V>::~SkipList() {
    if (_file_writer.is_open()) _file_writer.close();
    if (_file_reader.is_open()) _file_reader.close();

    //递归删除跳表链条
    if(_header->forward[0]!=nullptr){
        clear(_header->forward[0]);     // ← 递归！
    }
    delete(_header);
}

template <typename K, typename V>
void SkipList<K, V>::clear(Node<K, V> * cur)
{
    if(cur->forward[0]!=nullptr){
        clear(cur->forward[0]);         // ← 又递归！
    }
    delete(cur);
}
```

**这里的逻辑是**：从 L0 的第一个节点开始，沿着 `forward[0]` 一路递归下去，逐个删除。

**看起来没问题，但有个严重缺陷**：

递归深度 = **节点总数**。100 万个节点就是 100 万层递归，每层函数调用约占 48 字节栈空间：

```
100 万 × 48 字节 ≈ 48 MB
```

而 Linux 默认栈只有 **8 MB** → **栈溢出 → 段错误**。

> 我在你 VM 上实测过，`delete` 100 万节点的跳表直接 `exit=139`（段错误）。
> 复现代码：`tests/dtor_test.cpp`
>
> **修复方法**：改成迭代，不用递归。见 `docs/02-魔改路线图.md` 的 P1。

## ④ get_random_level()：掷硬币

```cpp
template<typename K, typename V>
int SkipList<K, V>::get_random_level(){
    int k = 1;
    while (rand() % 2) {        // rand()%2 为 1 就继续升层（1/2 概率）
        k++;
    }
    k = (k < _max_level) ? k : _max_level;    // 封顶
    return k;
};
```

和 `00-跳表入门.md` 讲的一致。**但这里有个小细节值得注意**：

`k` 从 **1** 开始（不是 0），意味着**每个节点的最小层高是 1**，也就是**至少有 2 层**（L0 和 L1）。

后果：**L1 必然包含所有节点**，和 L0 完全一样。

> 你在可视化程序的输出里能直接看到这个现象：
> ```
> L1 │ H ------>3 ------>6 ------>7 ------>9 ...   ← 和 L0 一模一样
> L0 │ H ------>3 ------>6 ------>7 ------>9 ...
> ```
>
> **L1 白白浪费了一个指针，没有起到任何"索引/跳跃"作用。**
>
> 经典跳表的写法是 `int k = 0;`，这样只有 1/2 的节点会出现在 L1 以上，
> 每一层才真正起到"稀疏索引"的作用。这是原项目的一个真实小缺陷，
> **面试时能主动指出这个，说明你真的读懂了，而不是背下来的。**

## ⑤ search_element()：查找（先读这个）

```cpp
template<typename K, typename V> 
bool SkipList<K, V>::search_element(K key) {
    std::cout << "search_element-----------------" << std::endl;
    Node<K, V> *current = _header;

    // start from highest level of skip list
    for (int i = _skip_list_level; i >= 0; i--) {
        while (current->forward[i] && current->forward[i]->get_key() < key) {
            current = current->forward[i];
        }
    }

    //reached level 0 and advance pointer to right node, which we search
    current = current->forward[0];

    // if current node have key equal to searched key, we get it
    if (current and current->get_key() == key) {
        std::cout << "Found key: " << key << ", value: " << current->get_value() << std::endl;
        return true;
    }

    std::cout << "Not Found Key:" << key << std::endl;
    return false;
}
```

### 逐行拆解

**第 1 步**：`current = _header` —— 从头节点出发。

**第 2 步**：外层 `for` 从**最高层** `_skip_list_level` 往下遍历到 L0。

**第 3 步**：内层 `while` —— **能往右就往右**：
```cpp
while (current->forward[i] && current->forward[i]->get_key() < key)
    current = current->forward[i];
```
- `current->forward[i]` 非空（右边有节点）
- **且**右边的 key **小于**目标 key

两个条件都满足就右移。一旦右边的 key `>= key`，就停下，降到下一层。

**第 4 步**：走完所有层后，`current` 停在 L0 上"最后一个 key < 目标"的节点。所以目标如果在，就是 `current->forward[0]`。

**第 5 步**：比较 `current->forward[0]->get_key() == key`。

### 为什么这样是对的？

因为**每层的链表都是有序的**。在高层"能跳就跳"，快速接近目标；到低层"小步走"，精确定位。

> 对应可视化程序打印的查找过程：
> ```
> 查找 19：
>   L3: -1 → 3   (3 < 19，继续右移)
>   L3: 停在 3（右边是 19 ≥ 19，下一层）
>   L2: 3 → 7    (7 < 19，继续右移)
>   ...
>   ✅ 找到 19
> ```
> 注意 `L3: 停在 3` 那一行——右边是 19，`19 < 19` 为假，所以**不右移**，直接降层。

### ⚠️ 这里有个并发问题

`search_element()` **完全没有加锁**。而 `insert_element()` 和 `delete_element()` 都加了锁。

这意味着：**一个线程在插入（改 forward 指针），另一个线程在查找（读 forward 指针），会产生数据竞争**，可能读到正在被修改的指针，轻则查错，重则崩溃。

> 我用 ThreadSanitizer 实测确认了这个问题（`tests/race_test.cpp`），TSan 报了 3 处 data race，栈顶就是 `search_element`。
> 修复方法：用 `std::shared_mutex` 读写锁。见 `docs/02-魔改路线图.md` 的 P1。

## ⑥ insert_element()：插入（最核心）

这是全文最难的函数，但拆开看就清楚了。

```cpp
template<typename K, typename V>
int SkipList<K, V>::insert_element(const K key, const V value) {
    
    mtx.lock();                                    // ← 加锁
    Node<K, V> *current = this->_header;

    // create update array and initialize it 
    Node<K, V> *update[_max_level+1];              // ← 关键：update 数组
    memset(update, 0, sizeof(Node<K, V>*)*(_max_level+1));  

    // start form highest level of skip list 
    for(int i = _skip_list_level; i >= 0; i--) {
        while(current->forward[i] != NULL && current->forward[i]->get_key() < key) {
            current = current->forward[i]; 
        }
        update[i] = current;                       // ← 记录每层的前驱
    }

    current = current->forward[0];
    ...
```

### 关键概念：`update[]` 数组

**查找**只需要找到目标；**插入**还需要知道**每一层该插在谁后面**。

`update[i]` 存的就是：**第 i 层中，最后一个 key < 目标 key 的节点**（也就是新节点在第 i 层的"前驱"）。

注意前 4 步和 `search_element()` **完全一样**，唯一的区别是多了一句 `update[i] = current;`。

```
插入 19（层高 3）时，update 数组大概是：

  update[3] = H        （L3 中 19 的前驱是头节点）
  update[2] = 7        （L2 中 19 的前驱是 7）
  update[1] = 17       （L1 中 19 的前驱是 17）
  update[0] = 17       （L0 中 19 的前驱是 17）

插入后：
  L3: H ─────────────────────────> 19
  L2: H ──> 7 ──────────────────> 19
  L1: H ──> ... ──> 17 ─────────> 19
  L0: H ──> ... ──> 17 ─────────> 19
```

### 继续读：判断 key 是否已存在

```cpp
    current = current->forward[0];

    // if current node have key equal to searched key, we get it
    if (current != NULL && current->get_key() == key) {
        std::cout << "key: " << key << ", exists" << std::endl;
        mtx.unlock();
        return 1;                                  // ← 返回 1 = 已存在
    }
```

**语义**：key 已存在 → 打印提示 → **返回 1，不覆盖旧 value**。

> 这就是前面说的"没有 update 语义"。**返回值约定**：`1` = key 已存在，`0` = 插入成功。

### 继续读：决定层高 + 抬高全表最高层

```cpp
    if (current == NULL || current->get_key() != key ) {
        
        int random_level = get_random_level();      // ← 掷硬币

        // If random level is greater thar skip list's current level, initialize update value with pointer to header
        if (random_level > _skip_list_level) {
            for (int i = _skip_list_level+1; i < random_level+1; i++) {
                update[i] = _header;                // ← 高出部分的前驱是头节点
            }
            _skip_list_level = random_level;        // ← 抬高当前最高层
        }
```

**为什么高出部分的前驱是 `_header`？**

因为原来 `_skip_list_level = 2`，只维护了 `update[0..2]`。现在新节点层高是 5，那么 L3、L4、L5 这三层的 `update[]` 是**没被赋过值的**（memset 成了 NULL）。

而 L3/L4/L5 目前**没有任何节点**（否则 `_skip_list_level` 就该是 5 了），所以新节点在这三层的前驱**只能是头节点**。

### 最后：逐层插入

```cpp
        Node<K, V>* inserted_node = create_node(key, value, random_level);
        
        // insert node 
        for (int i = 0; i <= random_level; i++) {
            inserted_node->forward[i] = update[i]->forward[i];   // ① 新节点指向原来的后继
            update[i]->forward[i] = inserted_node;               // ② 前驱指向新节点
        }
        std::cout << "Successfully inserted key:" << key << ", value:" << value << std::endl;
        _element_count ++;
    }
    mtx.unlock();                                  // ← 解锁
    return 0;
}
```

**这个两步指针操作就是标准的"链表插入"**，只是对每一层都做一遍：

```
插入前：  update[i] ──────> 原后继
插入后：  update[i] ──> 新节点 ──> 原后继
```

顺序**不能反**：必须先让新节点指向原后继，再让前驱指向新节点。反了的话原后继就丢了。

> **⚠️ 两个注意点**：
> 1. `Node<K,V>* update[_max_level+1];` 这是 **VLA（变长数组）**，是 GCC 的扩展，**不是标准 C++**，MSVC 不支持。`_max_level` 很大时栈开销也大。
> 2. `mtx.unlock()` 在**多个 return 路径**上都要记得写。上面"key 已存在"那条分支就手写了一次 `unlock()`——**这种手写加解锁很容易漏，一旦漏了就是死锁**。规范做法是用 RAII（`std::lock_guard`）。

## ⑦ delete_element()：删除

```cpp
template<typename K, typename V> 
void SkipList<K, V>::delete_element(K key) {

    mtx.lock();
    Node<K, V> *current = this->_header; 
    Node<K, V> *update[_max_level+1];
    memset(update, 0, sizeof(Node<K, V>*)*(_max_level+1));

    // start from highest level of skip list
    for (int i = _skip_list_level; i >= 0; i--) {
        while (current->forward[i] !=NULL && current->forward[i]->get_key() < key) {
            current = current->forward[i];
        }
        update[i] = current;
    }

    current = current->forward[0];
    if (current != NULL && current->get_key() == key) {
       
        // start for lowest level and delete the current node of each level
        for (int i = 0; i <= _skip_list_level; i++) {
            // if at level i, next node is not target node, break the loop.
            if (update[i]->forward[i] != current) 
                break;
            update[i]->forward[i] = current->forward[i];
        }

        // Remove levels which have no elements
        while (_skip_list_level > 0 && _header->forward[_skip_list_level] == 0) {
            _skip_list_level --; 
        }

        std::cout << "Successfully deleted key "<< key << std::endl;
        delete current;
        _element_count --;
    }
    mtx.unlock();
    return;
}
```

### 和插入的相似之处

前 4 步**又是完全一样**的：找路径、填 `update[]`。

> **发现规律了吗？** `search` / `insert` / `delete` 三个函数的**查找部分代码是一模一样的**。
> 这就是可以重构的地方——抽出一个 `find_predecessors(key, update[])` 函数。
> **面试时可以提这个重构点。**

### 摘链：`for (int i = 0; i <= _skip_list_level; i++)`

```cpp
if (update[i]->forward[i] != current) 
    break;                                    // ← 关键：该层没有这个节点就跳出
update[i]->forward[i] = current->forward[i];  // 前驱直接指向后继，跳过 current
```

**为什么会有 `break`？**

因为节点的层高是随机的。比如删除一个层高为 2 的节点，但 `_skip_list_level` 是 5：
- L0、L1、L2 上有这个节点 → 正常摘链
- L3 上**没有**这个节点 → `update[3]->forward[3] != current` → `break` 跳出

**为什么可以 `break` 而不是 `continue`？**

因为一个节点如果出现在第 i 层，它**必然也出现在所有更低的层**（层高是"从下往上"连续的）。所以一旦某层没有，更高的层也不会有，直接跳出即可。

### 收缩最高层

```cpp
while (_skip_list_level > 0 && _header->forward[_skip_list_level] == 0) {
    _skip_list_level --; 
}
```

如果删完之后，最高层**空了**（头节点在这一层的后继是 NULL），就把 `_skip_list_level` 降下来。

> 对应可视化程序里的输出：删除 3 之后打印了"最高层收缩"。
> 这个操作是**性能优化**：让 `search`/`insert` 的 `for` 循环不用从空层开始白跑。

## ⑧ dump_file() / load_file()：落盘与加载

### dump_file()

```cpp
template<typename K, typename V> 
void SkipList<K, V>::dump_file() {

    std::cout << "dump_file-----------------" << std::endl;
    _file_writer.open(STORE_FILE);                     // ← STORE_FILE = "store/dumpFile"
    Node<K, V> *node = this->_header->forward[0];      // ← 从 L0 第一个节点开始

    while (node != NULL) {
        _file_writer << node->get_key() << ":" << node->get_value() << "\n";
        std::cout << node->get_key() << ":" << node->get_value() << ";\n";
        node = node->forward[0];                       // ← 沿 L0 遍历
    }

    _file_writer.flush();
    _file_writer.close();
    return ;
}
```

**逻辑**：沿着 **L0**（包含所有节点）遍历，把每个节点按 `key:value` 格式写入文件。

**因为 L0 是有序的，所以写出来的文件也是有序的。**

> ⚠️ **两个问题**：
> 1. **没检查 `is_open()`**！如果 `store/` 目录不存在（比如你在别的目录运行程序），
>    `open()` 会失败，但代码**照样往下走、照样打印成功**，最后返回 void、进程退出码 0。
>    **数据一条都没写，你却以为落盘成功了** —— 静默丢数据。
>    我实测确认了这一点（`tests/dump_fail_test.cpp`）。
> 2. 每次调用都是**全量覆盖写**，不是增量日志。没有 WAL，进程崩溃 = 内存数据全丢。

### load_file()

```cpp
template<typename K, typename V> 
void SkipList<K, V>::load_file() {

    _file_reader.open(STORE_FILE);
    std::cout << "load_file-----------------" << std::endl;
    std::string line;
    std::string* key = new std::string();
    std::string* value = new std::string();
    while (getline(_file_reader, line)) {
        get_key_value_from_string(line, key, value);
        if (key->empty() || value->empty()) {
            continue;
        }
        // Define key as int type
        insert_element(stoi(*key), *value);            // ← 写死了 stoi
        std::cout << "key:" << *key << "value:" << *value << std::endl;
    }
    delete key;
    delete value;
    _file_reader.close();
}
```

**逻辑**：逐行读，用 `:` 切分，然后调 `insert_element` 插回跳表。

> ⚠️ **`stoi(*key)` 写死了 key 必须是 int**。如果你想用 string 做 key，必须改这里。
> README 的"待优化"也承认了这一点。

### 辅助函数

```cpp
template<typename K, typename V>
void SkipList<K, V>::get_key_value_from_string(const std::string& str, std::string* key, std::string* value) {
    if(!is_valid_string(str)) return;
    *key = str.substr(0, str.find(delimiter));                    // 冒号前面是 key
    *value = str.substr(str.find(delimiter)+1, str.length());     // 冒号后面是 value
}
```

注意 `str.find(delimiter)` 找的是**第一个**冒号。所以：
- **value 里可以有冒号**（会全部归到 value）
- **key 里不能有冒号**（会被截断）

### 一个历史遗留问题

仓库自带的 `store/dumpFile` 内容是这样的（**带分号**）：
```
1:a;
19:yang;
3:b;
```

但 `dump_file()` 写出来的是**不带分号**的：
```
1:学
3:算法
```

**两者格式不一致**。如果你直接调 `load_file()` 读那个自带的文件，value 会变成 `a;`、`yang;`（多一个分号）。

> 这是历史遗留，不影响主流程（因为 `main.cpp` 里 `load_file()` 是注释掉的），但**你复习时如果打开 load_file 发现 value 多了分号，就是这个原因**。

## ⑨ display_list() / size()

```cpp
template<typename K, typename V> 
void SkipList<K, V>::display_list() {
    std::cout << "\n*****Skip List*****"<<"\n"; 
    for (int i = 0; i <= _skip_list_level; i++) {
        Node<K, V> *node = this->_header->forward[i]; 
        std::cout << "Level " << i << ": ";
        while (node != NULL) {
            std::cout << node->get_key() << ":" << node->get_value() << ";";

}

}
```

`display_list()` 就是**把每一层打印出来**——这正是我的可视化程序在做的事，只不过它只打印数字，没画箭头。

## 全局变量（文件开头）

```cpp
#define STORE_FILE "store/dumpFile"

std::mutex mtx;                          // ← 全局锁
std::string delimiter = ":";             // ← 全局分隔符
```

**这两个都是"定义"而不是"声明"，写在头文件里是有问题的**：

每个 `#include "skiplist.h"` 的 `.cpp` 文件都会生成一份 `mtx` 和 `delimiter`。
当你有**两个** `.cpp` 都 include 了这个头文件并一起链接时：

```
/usr/bin/ld: multiple definition of `mtx'; first defined here
/usr/bin/ld: multiple definition of `delimiter[abi:cxx11]'; first defined here
collect2: error: ld returned 1 exit status
```

**这直接堵死了多文件工程化**——你想把它拆成 `kv_server.cpp` + `main.cpp` 就编不过。

> 我实测确认了（`tests/link_a.cpp` + `tests/link_b.cpp`）。
> 修复：C++17 加 `inline`，或者把定义移到 `.cpp` 里、头文件只留 `extern`。
>
> 另外，**一把全局锁被所有 `SkipList` 实例共享**，不同实例之间也会互相阻塞，粒度太粗。

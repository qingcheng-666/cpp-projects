## P1：修 4 个真实缺陷

### 1.1 迭代析构（替换递归）

**问题**：`clear()` 沿 level-0 递归，100 万节点爆栈（实测 exit=139）。

```cpp
// ❌ 原版
void SkipList<K,V>::clear(Node<K,V>* cur) {
    if (cur->forward[0] != nullptr) clear(cur->forward[0]);
    delete cur;
}

// ✅ 迭代版
template<typename K, typename V>
void SkipList<K, V>::clear(Node<K, V>* cur) {
    while (cur != nullptr) {
        Node<K, V>* next = cur->forward[0];   // 先存后继
        delete cur;                            // 再删当前
        cur = next;
    }
}
```

**验证**：把 `dtor_test.cpp` 的 100 万节点测试跑一遍，应从 `exit=139` 变成正常退出。

> 更稳的写法：也可以维护 `std::vector<Node*>` 收集所有 level-0 节点再统一 delete，但迭代已经够了。

### 1.2 头文件全局变量 → `inline`（C++17）

**问题**：`std::mutex mtx;` / `std::string delimiter = ":";` 定义在头文件，多 TU 链接报 multiple definition。

```cpp
// ❌ 原版（在 skiplist.h 里）
std::mutex mtx;
std::string delimiter = ":";

// ✅ C++17：头文件里用 inline 变量
inline std::mutex mtx;
inline const std::string delimiter = ":";
```

编译加 `-std=c++17`。

**更好的做法**：把锁和分隔符塞进 `SkipList` 类里做成员，彻底消除全局状态：

```cpp
template<typename K, typename V>
class SkipList {
    // ...
private:
    mutable std::shared_mutex _rwlock;   // 见 1.3
    static constexpr char kDelimiter = ':';
};
```

**验证**：`g++ a.cpp b.cpp -o t` 应链接成功（原版报 multiple definition）。

### 1.3 `shared_mutex` 读写锁

**问题**：`search_element` 不加锁，TSan 实测与写并发时是数据竞争，可能解引用野指针。

```cpp
#include <shared_mutex>

// 写操作
template<typename K, typename V>
int SkipList<K, V>::insert_element(const K key, const V value) {
    std::unique_lock<std::shared_mutex> lock(_rwlock);
    // ... 原逻辑
}

template<typename K, typename V>
void SkipList<K, V>::delete_element(K key) {
    std::unique_lock<std::shared_mutex> lock(_rwlock);
    // ... 原逻辑
}

// 读操作
template<typename K, typename V>
bool SkipList<K, V>::search_element(K key) {
    std::shared_lock<std::shared_mutex> lock(_rwlock);
    // ... 原逻辑
}

template<typename K, typename V>
void SkipList<K, V>::display_list() {
    std::shared_lock<std::shared_mutex> lock(_rwlock);
    // ...
}

template<typename K, typename V>
int SkipList<K, V>::size() {
    std::shared_lock<std::shared_mutex> lock(_rwlock);
    return _element_count;
}
```

**注意**：`insert_element` 内部如果调用 `search` 之类会**死锁**（非递归锁），改造时要确保加锁边界清晰 —— 建议把"无锁内部实现"和"加锁的公开接口"分成两层：

```cpp
private:
    int insert_element_nolock(const K& key, const V& value);
public:
    int insert_element(const K& key, const V& value) {
        std::unique_lock lock(_rwlock);
        return insert_element_nolock(key, value);
    }
```

`load_file()` 也调用了 `insert_element`，改完后它要么走 nolock 版本，要么自己先不持锁 —— 这是改造时最容易踩的坑，**务必测**。

**验证**：用 `setarch $(uname -m) -R ./race -fsanitize=thread` 重跑，TSan 警告应消失（这台 VM 需要关 ASLR 才能跑 TSan）。

### 1.4 `dump_file()` 返回 `bool` 并检查 `is_open()`

**问题**：`store/` 不存在时静默返回，数据没写、进程退出码 0。

```cpp
template<typename K, typename V>
bool SkipList<K, V>::dump_file() {
    std::shared_lock<std::shared_mutex> lock(_rwlock);
    _file_writer.open(STORE_FILE, std::ios::out | std::ios::trunc);
    if (!_file_writer.is_open()) {
        std::cerr << "[dump_file] cannot open " << STORE_FILE << std::endl;
        return false;                      // ← 关键：把失败暴露出去
    }
    Node<K, V>* node = _header->forward[0];
    while (node != nullptr) {
        _file_writer << node->get_key() << kDelimiter << node->get_value() << "\n";
        node = node->forward[0];
    }
    _file_writer.flush();
    bool ok = _file_writer.good();
    _file_writer.close();
    return ok;
}
```

顺带把 `dump_file()` 里那行 **重复打印到 stdout** 删掉（它同时写文件和打印，是性能与噪音双重浪费）。

**验证**：在不存在 `store/` 的目录下跑，应返回非 0 退出码并打印错误。

## P2：key 泛型化

**问题**：`load_file()` 写死 `stoi(*key)`，key 只能是 int；README 自己列为待优化。

**改法**：引入比较器/序列化策略，让 key 类型可插拔。

```cpp
template<typename K>
struct DefaultCodec {
    static std::string encode(const K& k) { return std::to_string(k); }
    static K decode(const std::string& s) { return static_cast<K>(std::stoll(s)); }
};

// string 特化
template<>
struct DefaultCodec<std::string> {
    static std::string encode(const std::string& k) { return k; }
    static std::string decode(const std::string& s) { return s; }
};

template<typename K, typename V, typename Codec = DefaultCodec<K>>
class SkipList { /* load_file 里用 Codec::decode */ };
```

同时把 `get_key_value_from_string` 里 `str.find(delimiter)` 的**首次匹配**改成**最后一次匹配**（`rfind`），这样 string key 含 `:` 时也能正确切分。

**面试话术**："我把 key 类型和磁盘编码解耦成 Codec 策略，支持 int/string 自定义类型。"

## P3：迭代器 + 范围查询（跳表的杀手锏）

**为什么重要**：跳表相对哈希表的核心优势就是**有序 + 范围查询**。原版只有 `display_list()` 能遍历，等于把最大卖点浪费了。

```cpp
template<typename K, typename V>
class SkipList {
public:
    class Iterator {
    public:
        explicit Iterator(Node<K, V>* n) : _node(n) {}
        bool operator!=(const Iterator& o) const { return _node != o._node; }
        Iterator& operator++() { _node = _node->forward[0]; return *this; }
        const K& key() const { return _node->get_key(); }
        const V& value() const { return _node->get_value(); }
    private:
        Node<K, V>* _node;
    };

    Iterator begin() const { return Iterator(_header->forward[0]); }
    Iterator end()   const { return Iterator(nullptr); }

    // 范围查询 [begin_key, end_key)
    std::vector<std::pair<K, V>> scan(const K& begin_key, const K& end_key) const {
        std::shared_lock lock(_rwlock);
        std::vector<std::pair<K, V>> out;
        Node<K, V>* cur = _header;
        for (int i = _skip_list_level; i >= 0; i--)
            while (cur->forward[i] && cur->forward[i]->get_key() < begin_key)
                cur = cur->forward[i];
        cur = cur->forward[0];
        while (cur && cur->get_key() < end_key) {
            out.emplace_back(cur->get_key(), cur->get_value());
            cur = cur->forward[0];
        }
        return out;
    }
};
```

**注意**：迭代器暴露裸指针，和并发删除一起用会悬空。要么文档里写明"迭代期间不允许写"，要么用引用计数。**这一点面试官很可能问**，提前想好答案。

**面试话术**："我加了 `scan()` 范围查询，实测 100 万数据下扫描 1000 条连续 key 只需 X 微秒，而哈希表要做全量过滤。"

## P4：WAL 预写日志（**最推荐的一步**）

**为什么重要**：原版 `dump_file()` 是全量覆盖，**进程崩溃 = 内存里所有未 dump 的数据全丢**。这是"存储引擎"和"玩具"的分界线。加上 WAL，你就可以正当地说"这是一个有崩溃恢复能力的存储引擎"。

### 设计

```
写路径：  写请求 → 追加 WAL（顺序写 + fsync）→ 写跳表 → 返回
恢复：    启动时 → 重放 WAL → 重建跳表
压缩：    WAL 超过阈值 → dump 全量快照 → 清空 WAL
```

### WAL 记录格式（建议）

```
+--------+--------+--------+--------+---------+---------+
| crc32  | op(1B) | klen   | vlen   | key     | value   |
| 4B     | PUT/DEL| 4B     | 4B     | klen B  | vlen B  |
+--------+--------+--------+--------+---------+---------+
```

带 CRC32 是关键 —— 崩溃时最后一条记录可能写了一半，恢复时要能识别并丢弃。

### 骨架代码

```cpp
class WAL {
public:
    explicit WAL(const std::string& path) : _path(path) {
        _out.open(path, std::ios::app | std::ios::binary);
    }

    bool append(char op, const std::string& key, const std::string& value) {
        std::string rec;
        uint32_t klen = key.size(), vlen = value.size();
        rec.append(reinterpret_cast<char*>(&klen), 4);
        rec.append(reinterpret_cast<char*>(&vlen), 4);
        rec += key; rec += value;
        uint32_t crc = crc32(rec);
        _out.write(reinterpret_cast<char*>(&crc), 4);
        _out.write(rec.data(), rec.size());
        _out.flush();                       // 真正要耐久需 fsync(fileno)
        return _out.good();
    }

    // replay：逐条读，CRC 校验失败即认为到尾部，停止恢复
    void replay(std::function<void(char, const std::string&, const std::string&)> fn);
private:
    std::string _path;
    std::ofstream _out;
};
```

**顺序**：**先写 WAL 成功，再改内存**。顺序反了就没有恢复能力。

**面试话术**："我实现了带 CRC32 校验的 WAL，先写日志再改内存；恢复时逐条重放，校验失败就截断。用 `kill -9` 打断写入进程后重启，数据能完整恢复到崩溃前最后一次成功写入。"

> 这是**可以现场演示**的东西，杀伤力极强。建议录个屏。

## P5：内存上限与统计

## P6：网络层 —— 和聊天室项目打通（**你的独特优势**）

这是把两个项目**串成一个故事**的关键：

```
聊天室项目（恋恋风辰）          本项目（Skiplist-CPP）
├── epoll / Reactor             ├── 跳表数据结构
├── 线程池                       ├── 并发控制
├── 协议设计（protobuf/json）     ├── 持久化 WAL
├── 业务逻辑                     └── 范围查询
└── 网络层 ✅                    └── 存储层 ✅
                ↘            ↙
              分布式 KV 存储服务
              （网络层复用聊天室经验，存储层用跳表）
```

**做法**：把跳表包成一个 KV Server，协议建议直接上 **Redis RESP 协议**（这样 `redis-cli` 就能直接连你的服务，演示效果拉满）。

```
客户端 redis-cli
      │ RESP
      ▼
┌─────────────────────────────────┐
│  KV Server (epoll + 线程池)      │
│  SET k v → insert_element       │
│  GET k   → search_element       │
│  DEL k   → delete_element       │
│  SCAN a b→ scan()               │
└──────────────┬──────────────────┘
               ▼
        SkipList + WAL
```

**为什么选 RESP**：协议简单（文本 + 长度前缀）、有现成客户端、`redis-cli` 可直接压测。你可以说"我实现了 Redis 协议的一个子集"。

**注意线程模型**：跳表已用 `shared_mutex` 保护，网络层多线程直接调即可；如果要极致性能，再考虑分片（每个 shard 一把锁）。

## P7：SSTable + Compaction（迷你 LevelDB）

做到这一步，项目就真的"深"了。**不要求全做完，能讲清楚设计就够**。

```
写入：MemTable(跳表) + WAL
        │ 超过阈值（如 4MB）
        ▼
     冻结为 Immutable MemTable
        │ 后台线程
        ▼
   SSTable（有序文件 + 稀疏索引 + Bloom Filter）
        │ 分层，L0 → L1 → L2 ...
        ▼
   Compaction（多路归并，丢弃被覆盖/删除的 key）
```

**读路径**：MemTable → Immutable → L0（新到旧）→ L1 → ... → 都不中则返回 not found。
**优化点**：每层 SSTable 加 **Bloom Filter**，避免无谓磁盘 IO。

**面试话术**："我把跳表当作 MemTable，配合 WAL 保证持久化，刷盘后形成 SSTable 并做分层 Compaction —— 这就是 LevelDB 的核心架构。"
